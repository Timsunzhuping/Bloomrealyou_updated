# Bloom 前台 AI 导购与客服

## 入口与能力

- 全站右下角橙灰色 Bloom 形象，首次进入普通页面自动欢迎；同一浏览器标签会话只自动打开一次，可关闭和再次打开。
- 选购商品、设计沟通、售后服务三个模式，中英西阿四种语言。支持连续对话、快捷问题、请求失败重试、清空会话。
- 推荐只使用后台在售商品及有效规格，最多展示三个商品。图片、起价、工艺、颜色、尺寸、生产天数由服务器商品资料提供，不采用模型生成的价格。
- 商品详情页的“问问 Bloom”传入当前商品，客户确认发送后咨询；商品卡可进入详情或设计器。购物车非空时才提供结算入口。
- 售后查询只显示当前购物会话最近五笔订单的编号、状态、时间和金额。不返回邮箱、地址、支付资料、设计源文件或其他客户订单。
- 不执行自动下单、付款、退款、补发或收费生图。“人工咨询”打开现有询价表单，不是实时人工转接，也不会自动创建客服工单。

## 配置真实模型

1. 管理后台“大模型配置”添加文本模型，填写已有适配器支持的豆包/方舟、OpenAI 兼容接口或 Anthropic 配置并测试连接。
2. 在“应用分配”将“销售与客服助手”绑定至该文本模型，保存。新请求立即使用该配置。
3. 服务端按既有模型中心规则加密保存 Key，主密钥 `MODEL_CONFIG_ENCRYPTION_KEY` 仅在服务器；前台无法获取模型 Key、主密钥或供应商地址。
4. 也可选择“服务器环境变量”，沿用模型中心的环境变量解析规则。未配置、停用、超时、输出格式错误时返回 `source: fallback`，前台标明“商品资料模式”，不冒充已调用真实大模型。
5. 本地预览默认 mock/未绑定真实模型，不代表已验证付费模型的实际生成质量。正式上线前使用测试账户验证已选模型、多语言、商品比较及售后答复。

详见 [模型中心配置说明](./model-configuration.md)。本功能复用现有适配器，不新增前端供应商调用。

## API 与安全边界

`POST /storefront-assistant/chat`，请求头 `x-cart-session` 必须是有效 UUID。正文：

```json
{
  "message": "团队活动想购买 30 件 T 恤，适合哪种？",
  "locale": "zh-CN",
  "mode": "shop",
  "productSlug": "classic-cotton-tee",
  "history": [{ "role": "user", "content": "我们需要印 Logo" }]
}
```

`productSlug` 为可选示例，请使用实际商品 slug。`history` 最多 12 条，只接受 user/assistant；消息上限 1800 字符，历史每条 2400 字符。响应为 `reply/source/products/orders/actions/cartItemCount`，`Cache-Control: no-store`。模型输出解析失败、推荐不存在的商品或未知动作均降级；动作链接由前端固定映射，不使用模型 URL。

模型上下文包含所选公开商品、本购物会话订单的最小状态字段、购物车件数、最近八条聊天；客户主动输入的内容也会发送给所选模型。界面提示不要发送密码、支付资料或完整地址。LLM 仍可能在自然语言中出错，价格以结算页为准，退款等需团队核实。正式运营需确认模型服务的数据处理协议与隐私告知。

当前平台前台没有真实客户登录，订单访问沿用既有匿名购物会话能力令牌。这不是完整账户鉴权，不能用一个订单编号查询其他设备的订单。当前实现为“进入平台自动欢迎”。后续接入真实登录时，应同时将服务器订单权限切换为已验证客户身份；成功登录后可发出 `bloom:customer-signed-in` 事件，浮窗取消在途请求、清空旧聊天并打开欢迎。

聊天文本只存当前浏览器的 `sessionStorage`，按语言和购物会话区分，最多 20 条；不持久化商品卡与订单卡，不存服务器聊天数据库。此新入口不调用旧 `/api/ai-agents` 全局会话/导出接口。旧接口仍须单独进行客户身份与权限安全审计，不能把本模块的隔离测试当作整个平台已通过安全审计。

## 限流与运维

只在 `.env.production.example` 和 Compose 示例添加非敏感限额：

```dotenv
STOREFRONT_ASSISTANT_DAILY_LIMIT=100
STOREFRONT_ASSISTANT_GLOBAL_DAILY_LIMIT=10000
```

单购物会话每天默认 100 次，全实例每天 10000 次；按 UTC 日计算。额外按 socket 来源地址每分钟 60 次、同购物会话一次在途请求、全实例最多 20 个在途请求限制，失败请求也计数。返回 429 的 `ASSISTANT_BUSY`/`ASSISTANT_RATE_LIMIT` 或 400 的 `ASSISTANT_SESSION_REQUIRED`；供应商错误只写泛化日志，不记录 Key 或原始客户聊天。

限流为进程内基础保护，重启会重置，多实例不共享；匿名购物会话可重建，因此不是可靠的账单额度系统。Nginx 后面 socket 地址通常是代理地址，会共享每分钟桶。本功能不信任客户端伪造的 X-Forwarded-For。规模化运营应加 Redis 持久配额、受信代理配置、网关限流、供应商账单上限和真实用户鉴权。

上线需要构建 shared、sdk、API、web，不需要新数据库迁移。保留现有服务器 `.env.production`，不覆盖真实 Key；按现有 Compose 发布流程升级 API/web 镜像，并保留旧镜像以便回滚。本次本地开发不自动修改线上服务器。

## 品牌素材

使用生成工具制作橙灰品牌小助手，透明背景 PNG：`apps/web/public/bloom-assistant.png`，384 像素方图。生成提示摘要：Bloomrealyou 品牌机器人，白色陶瓷、灰色面部、橙色耳机和开口圆环冠饰，友好微笑、挥手、头肩像、小尺寸可辨识、透明背景、无文字或水印。未重画或修改公司正式 Logo。

## 验收

- 首次欢迎、收起/再次打开、同会话刷新不重复自动弹窗。
- 商品快捷问题、当前商品咨询、设计器/详情跳转、中文和移动端布局。
- 模型中心绑定、供应商失败/无模型降级、失败消息可重试、不自动产生订单。
- 其他购物会话订单不泄露、模型上下文不包含订单地址/邮箱、请求不能加入 system 指令或 API Key 字段。
- 生产环境需另行验证真实模型、持久数据、跨域和代理限流策略。
